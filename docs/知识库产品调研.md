# 知识库产品调研与原型建议

调研日期：2026-10-09。范围：官方产品页、帮助文档与公开源码；没有进行账号登录体验、性能压测或准确率横向实验。本报告是能力与交互设计比较，不能据此排名回答准确率。功能会受版本、部署方式和套餐影响；未在公开资料中确认的能力不等同于不存在。

## 关键发现

1. 对我们的原型，最相关的参考组合是 RAGFlow 的文档模板、MaxKB 的上传预览向导、腾讯云的自选参数、WeKnora 的自动策略链和 FastGPT 的引用阅读器。这是产品设计建议，不是准确率排名。
2. 已核对的多数开发平台提供单问题检索测试和相关性排序。相关性分数依赖模型及检索器，不能当作有标准依据的 Recall@K。RAGFlow 官方也强调检查所需块是否召回、内容是否完整和排名是否合理，而不是单看分数。[检索测试说明](https://ragflow.io/docs/v1.0.0-rc1/retrieval_testing)
3. 生成关联问题、问题改写和独立评测题集用途不同。MaxKB 的关联问题及 FastGPT 的问题优化可用于增强检索；我们的评测题须在候选切分前生成并绑定统一原文依据，避免让某种切分占优。[MaxKB 生成问题](https://maxkb.cn/docs/v1/user_manual/dataset/doclist/)、[FastGPT 搜索测试参数](https://doc.fastgpt.io/zh-CN/openapi/dataset)
4. 公开文档没有足够证据说明上述所有产品普遍提供「同文档、多策略、内在质量评分、独立测试集、可回退索引」的一体化工作流。不能宣称这是行业首创；它可以作为我们原型重点验证的能力组合。
5. 文档解析质量是上游约束。百炼文档明确要求检查表格的表头、行列、数值和单位，以及原文定位信息。只调切块参数无法恢复解析阶段丢失的内容。[解析核验](https://help.aliyun.com/zh/model-studio/parse/results-and-best-practices)

## 对现有需求的建议

- 保留上传后的解析预览与模式选择，增加可解释的解析异常提示。
- 自选界面先展示文档模板，再展示候选策略；切分参数与检索参数采用不同设置区。
- 质量报告分为切块结构质量、测试集检索表现、回答引用支持度，避免一个总分掩盖失败环节。
- 引用应提供原文高亮及前后文。仅显示文档名或相似度不足以满足「引用准确率高」的验收目标。
- 对每次比较保存文档、解析、配置、模型、测试集和索引版本；试验配置在用户确认后发布。
- 暂不将权限连接器、知识图谱和复杂 Agent 流程纳入原型主线；可留作长期版需求。

## 尚需验证的事项

当前 200 MB／20 MB 及 WPS、OFD、压缩包要求仍是我们项目自己的需求，不能因为其他产品支持相似格式就认定解析组件已满足。需用样本核验 WPS／OFD、旧 Office、扫描 PDF、跨页表格及大型压缩包。临时索引保留 24 小时、最多 5 个等仍是我们之前提出的配置建议，不属于本次核实到的通用行业标准。模型商、存储位置、性能目标继续保留待定，未因调研自动改变需求。

本报告适合需求评审。下一轮产品实测应使用同一批文档和问题，记录解析缺失、引用定位、检索结果、耗时和成本，才能形成质量比较结论。
