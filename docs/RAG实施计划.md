# RAG 双模式切分与评测 Implementation Plan（草案）

> **For agentic workers:** 实施前阅读需求文档。本计划按可验收阶段组织；技术栈和数据边界仍待确定，因此当前版本用于排期与评审，不能直接作为逐文件编码清单。确定待定项后，使用 superpowers:executing-plans 或经用户明确要求的执行方式逐项落实。

**Goal:** 交付支持文档上传、模式选择、切分预览、多策略比较、原文引用问答和索引回退的 RAG 演示原型。

**Architecture:** 以统一解析结果和原文位置为核心数据层；自动切分、自选比较、测试题生成、索引构建及问答各自通过清晰接口衔接。候选索引与正式索引分离，采用后台任务构建和版本切换。

**Tech Stack:** 待定；选择须覆盖文档解析、异步任务、向量检索、模型调用、前端预览与状态持久化。

**Spec:** [RAG需求文档](RAG需求文档.md)

## Global Constraints

- 单独及批量上传：PDF、DOCX、PPTX、DOC、WPS、OFD 单文件最多 200 MB；XLSX、XLS、CSV、TXT、HTML、MD 单文件最多 20 MB。
- ZIP、TAR.GZ 内的文档须分别满足对应格式的单文件限制；压缩包总量与解压限制待定。
- 上传后先解析和画像，用户选择模式后才正式切分和建索引。
- 自动测试题的完整依据命中率须明确标注其测试集来源，不称为真实召回率。
- 任何回答引用必须可回到原文位置；证据不足时不得虚构引用。
- 模型提供商、存储位置、性能目标按需求文档保留待定；没有相应决策前，不完成依赖该决策的生产级集成。

## Review Focus

1. 压缩包内混合合法、超限、重复路径和恶意路径：逐条校验并报告结果，不丢失同批合法文件。
2. PDF／OFD／WPS 解析无法提供可靠文本或原文位置：报告不可评测状态，不输出虚假的定位与命中率。
3. 表格跨页或分段：表头、行列 ID 与引用定位保持一致。
4. 候选策略返回的文本量不同：比较时控制同一 Top-K 与上下文 token 预算。
5. 新索引构建中断或失败：旧正式索引继续服务，失败候选可清理或重试。

## 阶段 0：确认原型边界与技术选型

**产出：** 格式解析验证样本、技术选型记录、数据流图、演示验收题集草案。

- [ ] 收集每种文件格式至少一份代表性样本，覆盖扫描页、表格、标题、公式和长文档；用真实解析器验证文本与原文位置可提取。
- [ ] 确定模型服务、数据是否可外发、原文件／解析结果／索引存储位置及凭据管理方式。
- [ ] 确定压缩包总限制、异步任务并发和超时的原型值，并用样本文档测量处理时间。
- [ ] 确定实现技术栈与模块文件结构；将后续任务展开为精确文件路径、接口、测试命令和提交步骤。

**验收：** 技术选型能处理所有要求的格式，或明确列出解析缺口及补齐方案；数据流出与存储责任清晰。

## 阶段 1：上传、解析与文档画像

**产出：** 可批量上传的文档清单、解析结果、可定位原文、画像与状态展示。

- [ ] 先写上传校验测试：格式、单文件大小、批量局部失败、压缩包路径穿越及解压限制。
- [ ] 实现上传与后台解析任务；保存原文件、结构化内容、页码／段落／表格位置及解析版本。
- [ ] 先写画像测试：标题密度、章节标记、表格占比、短碎文本比例；实现只读画像生成。
- [ ] 展示解析预览和失败原因；用格式样本核对原文定位。

**验收：** 文件进入「等待选择模式」状态；任何解析失败均不产生空索引。

## 阶段 2：自动模式切分与索引

**产出：** 自动选策、切块质检、正式索引及首个可引用问答闭环。

- [ ] 为标题层级、启发式边界、递归兜底、表格行组建立统一切块接口与位置映射测试。
- [ ] 实现画像驱动的有序候选链和质检降级；分页符仅作为候选边界，避免切断句子和表格。
- [ ] 实现索引构建、问答检索和带原文位置的引用；测试证据不足与引用定位。
- [ ] 展示自动采用的策略、参数、质检结果和切块预览。

**验收：** 代表性文档完成上传到问答闭环；引用能定位到生成答案所用的原文。

## 阶段 3：自选参数、候选比较与快速评分

**产出：** 候选策略选择、参数编辑、切块预览、基础质量指标比较。

- [ ] 定义通用及策略专属参数校验，明确 token、字符与行数单位；测试重叠量、父子块大小及整篇切分边界。
- [ ] 实现同一文档的 2～3 个推荐候选与全部策略入口；单轮候选上限可配置。
- [ ] 实现切块预览、BI、SC、边界合理率和重复占比；评分定义与版本号入库。
- [ ] 如选用嵌入／共指模型，再实现 ICC、DCC、RC；缺项时按适用指标重新归一化，不以零分代替。

**验收：** 改参数只刷新预览；候选评分可复现且不把切块质量分称作检索准确率。

## 阶段 4：深入检索评测

**产出：** 自动生成测试集、各候选临时索引、完整依据命中率及成本对比。

- [ ] 在候选切分前由统一解析原文生成测试问题、预期答案和必要依据位置；测试重复题、无依据题与多依据题的过滤。
- [ ] 为候选异步建立临时索引；同一批问题在相同模型、Top-K 和上下文预算下运行。
- [ ] 实现完整依据命中率@K、平均依据覆盖率@K、完整命中倒数排名、耗时与资源统计。
- [ ] 前端展示题量、命中数／总题数和自动测试集局限；允许查看若干检索结果与原文依据。

**验收：** 同配置重复运行结果可复现；无足够合格题时不给出误导性的百分比。

## 阶段 5：发布、回退与临时资源清理

**产出：** 正式索引版本切换、回退、候选复用和定期清理。

- [ ] 以文档版本、解析版本、策略、参数和模型版本生成候选标识，复用完全相同的候选。
- [ ] 新候选索引通过可检索检查后原子切换为正式索引；测试失败时旧版本仍可回答。
- [ ] 保留上一个正式版本并提供回退操作；测试切换中并发问答的一致性。
- [ ] 按已确认的时间和数量限制清理未选中的临时索引，保留配置和评测记录。

**验收：** 多轮调参后资源数量受控；已清理方案能凭保存配置重建；回退后引用仍指向正确文档版本。

## 阶段 6：演示验收与长期版准备

**产出：** 原型演示脚本、人工核对记录、已知限制与长期版待办。

- [ ] 准备跨格式、跨结构的演示文档，覆盖自动模式、自选比较、引用定位和回退。
- [ ] 用人工核对的真实问题检查回答与引用是否一致；记录题目、证据、结果和失败类型。
- [ ] 统计各格式解析成功率、任务耗时、索引占用与模型调用成本，为性能目标提供依据。
- [ ] 将原型限制转为长期版需求：权限、多用户并发、监控、备份、数据删除、增量更新和容量规划。

**验收：** 演示流程可重复；引用准确率用人工核对样本报告，不用自动生成题目的分数替代。

## 依赖与顺序

阶段 0 → 1 → 2 是首个可用闭环；阶段 3 依赖统一切块接口；阶段 4 依赖候选索引与原文位置；阶段 5 依赖版本化索引；阶段 6 覆盖完整原型。各阶段结束时保留可演示的软件状态。当前不承诺具体工期，先通过格式样本和模型调用测量后估算。

## 实施前仍需补齐

本计划有意保留以下决策：模型与服务商、数据存储与外发、解析引擎、技术栈、性能目标、压缩包总限制、测试题及评分阈值、人工验收指标、索引保留时长。它们已在需求文档列出。确定后应把本计划展开为逐文件、逐测试的执行清单，再开始编码。
